You are a casual game designer for Saudi youth. Create a genuinely FUN, polished HTML mini-game. If it feels like a vocabulary test, you failed.

## CRITICAL: Make It a Real Game
The English words exist naturally in the game world — like items on a menu, labels on products, or things characters say. The player should NOT feel like they're "answering questions."

Think: Diner Dash, Cooking Fever, Fruit Ninja — games where you tap/swipe/collect, and language is just part of the environment.

## Juice Requirements (MUST implement at least 5)
Games that feel alive use "juice" — excessive visual feedback for every action:
1. **Combo counter**: 3-in-a-row = screen sparkles, 5-in-a-row = confetti explosion, 7-in-a-row = rainbow burst
2. **Flying items**: Correct item physically flies from its position to a collection area with an arc animation (@keyframes)
3. **Bouncy numbers**: Score/+10 text pops up with scale bounce, floats up and fades
4. **Character reactions**: Mascot emoji changes expression (happy/surprised/excited/sad) — use at least 4 different emoji
5. **Screen shake**: Subtle 2-3px shake on big moments (3-combo, level complete)
6. **Particle effects**: Small emoji particles burst from tap point on correct (use 5-8 small absolutely positioned spans that animate outward and fade)
7. **Tray/basket fill**: Visual collection area that shows items accumulating — empty → partially filled → full → celebration
8. **Sound-like visuals**: Pulsing rings, color flashes, screen dim/brighten to simulate audio cues

## Structure: Mobile Game Flow (REQUIRED)
Implement as a real mobile game with multiple screens:

**Screen 1 — Splash/Loading (1.5-2s)**
- Game title + large emoji + "Loading..." with a simple CSS spinner
- Fade out → transition to game

**Screen 2 — Main Game**
- The gameplay as described

**Screen 3 — Results**
- Collection showcase, stats, CTA button

Use CSS transitions (opacity + transform) between screens. No page reloads.
All screens are divs inside #app, toggled with class "active".

### Sound Effects via Web Audio API
Generate short sounds programmatically (no audio files!):
```js
const AudioCtx = window.AudioContext || window.webkitAudioContext;
let actx;
function playBeep(freq, type, duration) {
  if(!actx) actx = new AudioCtx();
  const osc = actx.createOscillator();
  const gain = actx.createGain();
  osc.type = type; osc.frequency.value = freq;
  gain.gain.value = 0.3; gain.gain.exponentialRampToValueAtTime(0.001, actx.currentTime + duration);
  osc.connect(gain); gain.connect(actx.destination);
  osc.start(); osc.stop(actx.currentTime + duration);
}
function sfxCorrect() { playBeep(660, 'sine', 0.15); setTimeout(()=>playBeep(880, 'sine', 0.2), 100); }
function sfxWrong() { playBeep(200, 'triangle', 0.3); }
function sfxCombo() { playBeep(1100, 'sine', 0.1); setTimeout(()=>playBeep(1320, 'sine', 0.15), 80); }
function sfxCollect() { playBeep(520, 'sine', 0.08); }
```
- sfxCorrect() on correct tap
- sfxWrong() on wrong tap
- sfxCombo() on hitting 3/5/7 streak
- sfxCollect() when item flies to collection tray

## Mobile Optimization (REQUIRED)
- viewport: `<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">`
- Set `touch-action: manipulation` on all interactive elements (kills 300ms delay, prevents double-tap zoom)
- Minimum touch target: 48x48px (Apple HIG) for all clickable elements
- Body: `overflow: hidden` to prevent unwanted scroll
- Full container height: use `100dvh` (dynamic viewport height for iOS Safari)
- Safe area padding: `padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left)` on the main container
- Add to `<head>`: `<meta name="apple-mobile-web-app-capable" content="yes">` and `<meta name="apple-mobile-web-app-status-bar-style" content="default">`
- Test assumption: most players use phone in portrait mode, one-handed
